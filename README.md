# XVR Viewer — تطبيق أندرويد لعرض وتسجيل كاميرات XVR محلياً

تطبيق Kotlin + Jetpack Compose + Room + MVVM يتصل مباشرة بجهاز الـ XVR/DVR عبر بروتوكول
RTSP، ويعرض البث المباشر، **ويسجّل الفيديو تلقائياً وباستمرار على تخزين الهاتف المحلي بدون
أي أمر أو تدخل يدوي** (بمجرد فتح التطبيق مرة واحدة وإضافة الكاميرات، تعمل خدمة أمامية في
الخلفية تُعيد الاتصال تلقائياً وتحذف أقدم التسجيلات عند امتلاء الحصة المخصصة، تماماً كجهاز
DVR حقيقي).

## كيف يعمل التسجيل التلقائي
- `RecordingService` خدمة أمامية (Foreground Service) تبدأ فور فتح التطبيق، وتُعاد تلقائياً
  عند إعادة تشغيل الجهاز عبر `BootReceiver`.
- لكل كاميرا مفعّلة، `StreamRecorder` يتصل بالـ XVR عبر `RtspClient` (تطبيق RTSP/RTP كامل من
  الصفر بدون أي مكتبة خارجية)، يفكك حزم H264 عبر `H264RtpDepacketizer`، ويكتبها مباشرة إلى
  ملف MP4 عبر `MediaMuxer` القياسي في أندرويد.
- كل 5 دقائق (قابل للتعديل) يُغلق الملف الحالي ويُفتح ملف جديد تلقائياً، ويُسجَّل في قاعدة
  بيانات Room.
- عند تجاوز حصة التخزين المخصصة للكاميرا، تُحذف أقدم التسجيلات تلقائياً (تسجيل دائري).

> **لماذا لا يستخدم المشروع FFmpeg؟** مكتبة `ffmpeg-kit` (الأشهر لهذا الغرض) تم إيقافها
> نهائياً من قبل المطور الأصلي في أبريل 2025 وأُزيلت من Maven Central، لذلك تم بناء عميل
> RTSP ومُفكِّك H264 مباشرة بلغة Kotlin باستخدام `MediaMuxer` الرسمي من أندرويد — أكثر
> استقراراً على المدى الطويل ولا يعتمد على مكتبة متوقفة.

## هيكل المشروع
```
app/src/main/java/com/mohammed/xvrviewer/
├── data/          # Room: Camera, Recording, DAOs, Repository
├── rtsp/          # عميل RTSP + مفكك H264 + المسجّل (StreamRecorder)
├── service/       # RecordingService (خدمة أمامية) + BootReceiver
├── viewmodel/      # CameraViewModel, RecordingViewModel
├── ui/            # شاشات Compose (قائمة الكاميرات، إضافة، بث مباشر، تسجيلات، تشغيل)
├── MainActivity.kt
└── Navigation.kt
```

## طريقة التشغيل
1. افتح المجلد في Android Studio (Koala أو أحدث).
2. اضغط Sync ثم Run على جهاز حقيقي (RTSP لا يعمل جيداً على المحاكي عادة بسبب الشبكة).
3. من داخل التطبيق اضغط + وأدخل: عنوان IP الخاص بالـ XVR، المنفذ (افتراضي 554)،
   رقم القناة، اسم المستخدم وكلمة المرور.

## صيغة رابط RTSP
التطبيق يبني الرابط تلقائياً بالصيغة الشائعة لدى أغلب أجهزة XVR الصينية
(Dahua/بعض الأنواع المتوافقة معها):
```
rtsp://username:password@IP:PORT/cam/realmonitor?channel=X&subtype=0
```
إن كان جهازك يتبع صيغة أخرى (مثلاً Hikvision: `/Streaming/Channels/101`)، يمكنك تعديل دالة
`buildRtspUrl()` في `Camera.kt` أو إضافة حقل "مسار مخصص" في شاشة الإضافة (الحقل `streamPath`
موجود بالفعل في الكيان وجاهز للربط بالواجهة).

## محددات مهمة يجب معرفتها قبل الاستخدام الفعلي
- **الفيديو فقط بدون صوت حالياً**: `StreamRecorder` يسجل مسار H264 فقط. إضافة الصوت (AAC)
  ممكنة لاحقاً بنفس الطريقة (قناة RTP إضافية + مسار صوت في MediaMuxer).
- **يدعم H264 فقط** (ليس H265/HEVC). أغلب أجهزة XVR تسمح باختيار H264 من إعدادات الجهاز
  نفسه لقناة الـ substream.
- **النقل عبر TCP فقط** (أكثر توافقاً وأماناً خلف الراوتر من UDP، لكنه قد يستهلك بيانات أكثر
  قليلاً في حال فقدان الحزم).
- المصادقة تدعم Basic و Digest (الأكثر شيوعاً في هذه الأجهزة).
- **الدقة المضبوطة في MediaFormat هي 1920x1080 كقيمة أولية**؛ MediaMuxer عادة يتكيف مع
  الدقة الفعلية القادمة من SPS، لكن يُفضّل ضبطها لتطابق دقة الـ substream الفعلية من إعدادات
  جهازك لتفادي أي تشويه، خصوصاً إن كنت تستخدم القناة الرئيسية (subtype=0) بدقة مختلفة.
- **الاختبار مطلوب على جهازك الفعلي**: أجهزة XVR تختلف قليلاً في صيغة SDP والمصادقة بين
  الشركات المصنّعة (Dahua/Hikvision/OEM محلي)، لذلك يُنصح بتجربة الاتصال أولاً بتطبيق مثل
  VLC للتأكد من رابط RTSP الصحيح قبل إضافته للتطبيق.
